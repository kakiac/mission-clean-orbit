# Teacher Notes - Releasing Team Solutions After the Session

## Purpose
This file supports staged delivery so students first attempt tasks independently, then review model answers.

## Recommended classroom flow
1. Keep students focused on files in `/teams/` during active workshop.
2. Do not direct learners to `/solutions/` until reflection stage.
3. After presentations, reveal solution files for comparison and self-assessment.

## Practical reveal options
- **Option A (simple):** verbally share the `/solutions/` path at the end.
- **Option B (controlled):** keep solutions on a separate branch and merge after session.
- **Option C (release style):** publish solutions in a timed commit after class.

## Suggested debrief questions
- Which team decisions had the biggest impact on final quality?
- Which defects were easiest/hardest to detect?
- How did agile check-ins improve collaboration?
- What would you change in a second sprint?

## Assessment evidence suggestions
- Screenshots of working dashboard states
- Team check-in records and QA logs
- Student explanations of code and design choices
- Reflection notes linking technical and employability skills
